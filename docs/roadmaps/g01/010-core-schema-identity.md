# g01.010 Core Schema Identity and Publication

Owner: repo maintainers
Created: 2026-09-18
Governing refs: `docs/architecture/core-package-vocabulary.md`,
`docs/contracts/002-package-boundary.md`
Depends on: nothing local; it crosses repository boundaries
Ready state: blocked — operator decision plus a Market/Silo planning record

## Outcome

Core schemas carry this package's identifiers and are generated and published
here, so a consumer's namespace stops sitting on the core's own shapes.

## Why this is blocked

This package ships no schemas at all. Core schemas carry an Acowtancy-local
identifier and are generated by a crate in the Acowtancy repository. The
direction is settled — the authority cannot be a mirror — but three things are
not:

1. **The namespace.** The exact package-owned spelling that replaces the local
   one.
2. **The generation home.** Which crate or script generates the schemas, and
   where the generated output is published.
3. **The publication shape.** Whether this package ships schemas, or consumers
   generate them from a pinned source.

Acowtancy consumes this package, and Silo's pin and consumer mirrors carry
whatever identifier wins, so this cannot be decided in this repository alone.

## Ready-state rubric

- [ ] Namespace decision recorded with its exact spelling.
- [ ] Generation home named, with the retained evidence for it.
- [ ] Publication shape decided.
- [ ] Market/Silo follow-up recorded before any local work starts.

## Next step

Operator decision on the namespace and the generation home. Cross-repository
