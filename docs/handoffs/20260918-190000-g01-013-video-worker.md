## What This Thread Was Doing

The media family was three blocks wearing one name. `download_card` and `image` landed in g01.008 and
g01.012. This lane adds `video`: an embed addressed by provider and id, using Poodle's own embed model.

## Why It Matters

It completes the media vocabulary the release ships, and it is the last block type the release adds —
which matters to the schema lane behind it, because that lane publishes a payload document for every
declared core block type and cannot pass while a type is declared without one.

## Boundaries

- **In scope:** the `video` editor and renderer, their registrations, the capability flags, the
  side-effect entries, and the component and sanitization tests.
- **Out of scope:** direct-file playback, `audio`, the media-source registry, the library-backed blocks,
  the table and item-list editors, `ts/src/styles.css`, the Rust crate, the wire fixtures, the schema
  lane, release or version changes, and every consumer repository.
- **Repo constraints:** follow `AGENTS.md` and contracts 002 and 003. `renderEmbed` returns HTML, so it
  goes through the existing sanitizer before `{@html}` — without exception. The renderer carries no
  scoped styles, no class and no new token; it emits `data-nightfire-block="video"`. The render path must
  not import an editor module.
- **The model is Poodle's.** `ParsedEmbed` is `{ provider, id, originalUrl?, originalEmbed?, width?,
  height?, embedType? }`, and the feature set is declared and validated in Poodle core. Do not define a
  provider list, a parser, an embed shape or a URL regex under `ts/src`.
- **No library.** An embed is addressed by provider and id, so the media-source registry is not involved.

## Important Context

- **Planning lineage:** the operator settled the media vocabulary on 2026-09-18 — `download_card` and
  `image` use the library hooks, and the embeds do not. The `media` type this replaces is retired.
- **Block data:** `{ embed: ParsedEmbed, title?, caption? }`. `title` becomes the embed frame's
  accessible name; `caption` is visible text under it.
- **Authoring** uses `EmbedInput`, with the allowed provider list supplied by the consumer. An
  unparseable value must store nothing rather than a partial embed, so the editor surfaces the parse
  error and leaves the block unchanged.
- **Direct-file playback is deliberately not this block.** A consumer that wants `<video src>` uses
  Poodle's `VideoPlayer` inside its own profile block. Widening this type to cover both would make one
  type mean two things, which is what retiring `media` was meant to stop.
- **Open tensions:** none for this lane. `audio` stays unbuilt until the operator asks for it.

### UI design brief (compact)

- **Classification / current and target workflow:** refinement. The author pastes a URL, sees the parsed
  provider, and optionally adds a title and caption.
- **Presentation direction and design authority:** semantic markup, the
  `data-nightfire-block="video"` hook, no scoped styles, no class, no token of this package's own.
- **States, content ranges, and input envelope:** empty value → nothing rendered; unparseable value →
  the editor shows the error and stores nothing; parsed → the embed renders with the title as its
  accessible name. Long captions wrap.
- **Selected concept or prototype identity:** none required at this classification.
- **Scenario oracle:** paste a supported URL, confirm the provider is detected, save, reload, and see the
  same embed rendered. Then paste an unsupported URL and confirm the editor refuses it rather than
  storing a partial value. Then confirm a hostile embed value is sanitized.
- **Open decisions and stop conditions:** none. Stop rather than widening the type.
