## What This Thread Was Doing

`table` renders and has never been editable, so the only way to produce one is to hand-write its JSON.
This lane adds the first grid editor in the package: a direct-manipulation table where the author types
into cells, adds and removes rows and columns, marks header rows, sets alignment, and sets per-edge
borders.

The renderer is complete and does not change.

## Why It Matters

Four of the five generic text and layout blocks now have an editor. The table is the one that makes the
package's layout vocabulary real for an author rather than for a schema author, and it is the first
editor whose actions can destroy content, so it is also where the package has to answer for that.

## Boundaries

- **In scope:** the table editor, its registration, its `sideEffects` entry, the `table` `editor`
  capability flag, and its tests.
- **Out of scope:** cell spans, column widths, authorable row sections, the `item_list` editor, the
  renderer, the media lanes, the Rust crate, the wire fixtures, release or version changes, and every
  consumer repository.
- **Repo constraints:** follow `AGENTS.md` and contracts 002 and 003. The **renderer** stays untouched
  and keeps its rules; the **editor** may carry scoped styles, as the other editors do. Do not add a
  dependency.
- **No silent field loss.** The editor writes the fields it manages and preserves every other field in
  a row or cell it is rewriting. `section` is the specific trap: it is not authored here and must
  round-trip unchanged.
- **No undo exists.** Do not invent an undo facility in this lane. Protect by construction instead.

## Important Context

- **Planning lineage:** the operator settled the four material questions on 2026-09-18 (direct grid;
  markdown cells; per-edge borders needed and named sections not; no column widths). The full brief is
  in the card.
- **The interaction model.** One cell has focus. Arrow keys move a cell; Tab and Shift+Tab move forward
  and back, adding a row when Tab leaves the last cell. Typing or Enter enters edit mode; Escape leaves
  it. While editing, the cell shows raw markdown; while not editing, it renders markdown through the
  same sanitize path the renderer uses.
- **Structural actions.** Insert above, below, left and right, and remove, on the focused row and
  column. Removing a row or column that holds content asks for confirmation first, in-page and not with
  a browser dialog.
- **Header rows are a row-level toggle** that sets `is_header` on every cell in that row at once,
  because the renderer infers the head group from all-cells-header. More than one header row is valid.
- **Borders are content, not theme.** The focused cell carries four edge toggles plus a clear action,
  writing `borders`. This is exactly the split contract 003 rule 3 describes, so the control belongs in
  the editor and the appearance stays with the consumer.
- **New tables start as two columns by two rows with a header first row**, so there is always somewhere
  to type.
- **Accessibility is acceptance, not polish.** A hand-rolled grid is where this usually fails:
  `role="grid"`, `role="row"`, `role="gridcell"`, header cells exposed as headers, a roving tabindex so
  the grid is one tab stop, keyboard access to every structural action, and a visible focus indicator
  that survives the consumer's stylesheet.
- **Open tensions:** spans are deliberately excluded, and removing a content-bearing row is the one
  destructive action this lane ships.

### UI design brief

- **Classification / current and target workflow:** workflow change. There is no current authoring
  workflow — the block is JSON-only — and the target is the grid described above.
- **Presentation direction and design authority:** reuse the package's existing editor chrome and
  Poodle controls rather than inventing a second visual language; mirror Poodle's rich-text table
  command vocabulary (`insert-table`, `add-row`, `add-column`, `delete-table`) so labels agree. The
  rendered table's appearance stays the consumer's.
- **States, content ranges, and input envelope:** a new table renders the starting grid, never blank; a
  cell's markdown may be empty; a row with no cells or a table with no rows must not crash the editor;
  long cell text wraps and the grid scrolls horizontally instead of squeezing columns.
- **Selected concept or prototype identity:** none; the operator chose the direct grid from three
  described structures.
- **Scenario oracle:** without a mouse, start a table, type a header, type a body cell, add a row with
  Tab, add a column, mark the second row as a header row, centre one cell, give one cell a bottom edge,
  remove an empty row, then save and reload. The data must contain the typed markdown, both header
  rows, the alignment and that one edge, and no section value the author did not write. Then remove a
  content-bearing row and confirm the confirmation appears.
- **Open decisions and stop conditions:** none outstanding. Stop rather than inventing an interaction
  the brief does not settle, and stop rather than adding spans, widths or sections.
