## What This Thread Was Doing

g01.008 retired the extracted `media` type and added `download_card` plus the media-source registry.
This lane adds `image`: one image held as a media-library reference, with alt text, an optional title
and caption, and opt-in sizing. It resolves through the same registry, and it supplies the image
insert path for `rich_text`.

## Why It Matters

An image is content in flow, and its file facts belong to the library that owns them. Holding a
reference instead of a URL means a file moved or renamed in the library updates every block showing
it, and a reference that cannot be resolved renders inert instead of breaking a page.

It also closes a loop the previous lane opened: `rich_text` admits the image feature, and Poodle's
image node takes `src`, `alt` and `title`. Until Nightfire supplies that host function, an author can
see the feature in the vocabulary and cannot use it.

## Boundaries

- **In scope:** the `image` editor, renderer and empty checker; the additive registry extension;
  supplying Poodle's `requestImage` from the registry; the declaration flags and side-effect entries
  for the new modules.
- **Out of scope:** `video`, the download card's own behaviour or fields, the `table` and `item_list`
  editors, the Rust crate, the wire fixtures, `ts/src/styles.css`, release or version changes, and
  every consumer repository.
- **Repo constraints:** follow `AGENTS.md` and contracts 002 and 003. The renderer carries no scoped
  styles, no class and **no style attribute at all** — not even a defensive `max-inline-size`. It
  emits `data-nightfire-block="image"` and `data-sizing="<preset>"`, and the consumer's stylesheet
  decides what a preset means. The render path must not import an editor module. Do not add a
  dependency.
- **Extend, do not fork:** g01.008's registry is resource-scoped and already carries two fields' worth
  of shape for downloads. Add what images need — an optional `filterKind` on the picker, and `width`,
  `height` and `title` on the resolved record if they are absent — without renaming or reshaping what
  is already there, and keep the download card's tests passing unchanged.
- **Block data:** `{ media_id, alt?, title?, caption?, sizing? }`. A URL is never stored.

- **How the plan fits the system:** `ts/src/core-blocks.ts` is the declaration, and
  `ts/tests/nightfire/core-self-registration.test.ts` asserts it in both directions. Flip the `image`
  flags only in the change that registers each part.
- **Two constraints that are easy to miss.** `resolve` is synchronous, so the renderer stays simple
  and SSR-safe; an unknown reference renders inert rather than suspending. And the preset is a hint,
  not a width: emitting a style from the renderer would break contract 003 rule 4.
- **Intrinsic dimensions are used, not stored.** When the source resolves `width` and `height`, emit
  them so the page does not shift while the image loads. A source without them renders without them.
- **Open tensions:** none for this lane. The download card's per-file `title` is g01.014 and must not
  be added here.

### UI design brief (compact)

- **Classification / current and target workflow:** refinement. The author picks an image from the
  library, writes alt text, optionally a title and caption, and optionally a size. The picker pattern
  is the download card's.
- **Presentation direction and design authority:** semantic markup, the
  `data-nightfire-block="image"` hook, and the preset as `data-sizing`. Appearance is the consumer's.
- **States, content ranges, and input envelope:** no `media_id` → nothing rendered; no registered
  source or an unresolvable reference → inert and marked by a data attribute; resolved → the image
  renders with intrinsic dimensions when available; sizing absent → natural. One image per block.
- **Selected concept or prototype identity:** none required at this classification.
- **Scenario oracle:** register a source, pick an image, add alt text and `sizing="medium"`, save,
