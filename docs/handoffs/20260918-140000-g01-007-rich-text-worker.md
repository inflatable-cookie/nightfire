## What This Thread Was Doing

Nightfire is a released standalone package, and its core vocabulary is declared
but partly unimplemented. `ts/src/core-blocks.ts` declares six generic block
types and, per type, which parts exist. `rich_text` is the largest gap: it
declares no renderer, no editor, and no empty checker, while every other declared
part of the vocabulary has landed.

This lane implements the `rich_text` block: a renderer and an editor over
Poodle's published feature-gated rich-text surface, registered so the
declaration and the catalog agree.

## Why It Matters

The package's whole claim is that it is the authority for a generic block
vocabulary. A declared type with no implementation is the specific failure the
declaration exists to prevent: a consumer can select `rich_text` from the
vocabulary and get nothing. Until it lands, the vocabulary is a list of
intentions rather than a contract.

It also unblocks two dependent lanes. The media-source seam in
[g01.008](../roadmaps/g01/008-media-source-seam-and-shells.md) exists because the
rich-text image node consumes it, and the layout editors in
[g01.009](../roadmaps/g01/009-layout-block-editors.md) share the same declaration
and catalog files, so this lane must land first.

## Important Context

- **Planning lineage:** the core vocabulary was declared in
  `docs/architecture/core-package-vocabulary.md`, promoted 2026-09-18, and the
  self-registration mechanism landed with it. `0.1.0` is released; this work is
  post-release and unreleased.
- **How the plan fits the system:** the declaration in `ts/src/core-blocks.ts` is
  the contract. A capability flag and the registration that satisfies it must
  change in the same commit, because
  `ts/tests/nightfire/core-self-registration.test.ts` asserts both directions —
  every declared capability is registered, and nothing undeclared is registered.
- **Decisions and preferences:** the document is stored at `data.document` as
  ProseMirror document JSON. The admitted feature set is Poodle's exported
  `RICH_TEXT_FEATURES` — the whole set, images included. Poodle omits the
  image-insert command while no `requestImage` host function is present, so this
  lane ships an inert image node rather than a second engine. Wrapping Poodle is
  the whole job: no local node, mark, feature, schema, or toolbar definition.
- **Open tensions:** nothing material is open for this lane. The one genuinely
  open vocabulary question — whether the existing `media` block keeps its `alt`
  and `display` fields — belongs to g01.008 and must not be decided here.

### UI Design Brief

- **Classification / current and target workflow:** none. This is component
  wiring rather than a new experience. The author's editing experience is
  Poodle's `RichTextEditor` with a pinned feature set; Nightfire adds no entry
  point, action, or presentation of its own. The appearance contract is contract
  003, and the consumer owns the tokens.
- **Presentation direction and design authority:** Poodle's component and the
  consumer's `--nightfire-*` values. Nightfire emits no scoped styles.
- **States, content ranges, and input envelope:** empty document, structured
  document, read-only render, and disabled editor are Poodle's own states. No new
  state is introduced.
- **Selected concept or prototype identity:** none; none is required at this
  classification.
- **Scenario oracle:** with the block registered, an author edits a document
  containing a heading, a list, and a link; the saved block's `data.document`
  remains ProseMirror document JSON; the renderer renders it with no editor code
  in the renderer graph.
- **Open decisions and stop conditions:** none for this lane. Stop if a material
  experience decision appears, rather than inventing one.
