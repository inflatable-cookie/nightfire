## What This Thread Was Doing

The editor chrome's default appearance is `ts/src/styles.css`: 23 `--nightfire-*` tokens, consumed only by
editor surfaces and by no renderer. The operator confirmed the stylesheet stays, and that its tokens are
overridable defaults rather than a theme this package owns against a consumer.

This lane is the audit that remainder implies, and it is the last implementation lane before the release.

## Why It Matters

Two concrete defects are live in shipped chrome, and one of them violates a contract:

1. **A referenced token does not exist.** `ts/src/layout/TableEditor.svelte` reads
   `--nightfire-color-focus`. It is not declared in `ts/src/styles.css`. Contract 003's acceptance says a
   renderer is not complete until every presentational value comes from the token set or is added to it in
   the same change. A consumer has no declared name to override for the focus ring, and the
   `currentColor` fallback is the only reason it renders.
2. **Fallbacks are a second declared value.** Five `currentColor` fallbacks exist package-wide, and
   earlier components carry dark fallbacks while the shipped palette is light. Because the stylesheet
   loads for anyone following `README.md`, those fallbacks are dead code — and a silent, differently
   coloured theme for anyone who does not.

It is also the point where the token names become settled public API, since a consumer override binds to a
name.

## Important Context

- **The naming decision: keep the six app-shaped names.** `color-surface`, `color-surface-secondary`,
  `color-danger`, `color-field-bg`, `button-chip-padding-block` and `button-chip-padding-inline` are
  ordinary editor-chrome concepts even though the values arrived from an application stylesheet, and a
  rename is a breaking change that buys vocabulary tidiness rather than capability. Record that in
  contract 003 as a decision, not a default.
- **The values are defaults, and the names are the API.** A consumer overrides by re-declaring a name, so
  the values can change freely and the names cannot. State this where a consumer will read it.
- **Document the Poodle mapping as a recipe, not a dependency.** The editors embed Poodle components, so
  the two vocabularies describe the same concepts: `--poodle-color-status-danger` beside
  `--nightfire-color-danger`, `--poodle-color-border-default` beside `--nightfire-color-border-subtle`. A
  wrapper-scoped recipe of a few declarations gives a consumer alignment for the cost of a few lines; a
  `:root` override depends on stylesheet load order, so document the wrapper.
- **One declared value per token.** Either no fallback, or one that matches the stylesheet. A fallback that
  disagrees is worse than none, because it silently decides the appearance when the stylesheet is absent.
- **The audit has to cover later lanes.** The video and item-list editors landed before this lane runs, so
  include their chrome; do not fix only what the table editor exposed.
- **Open tensions:** none. The values' upstream relationship is provenance, and the Poodle alignment is a
  documented recipe rather than a dependency.
